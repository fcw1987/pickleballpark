# Cache acceptance audit · final resolved-cache memory fix

Accepted for the current authored scene after a public-Three.js memory fix and fresh isolated Playwright Chromium checks. The earlier four-test acceptance did not exercise a native DPR3 phone: at 390 × 844 CSS pixels, its 1170 × 2532 backing buffer required a persistent MSAA cache estimate of 118,497,600 bytes (113.0 MiB), exceeding the 96 MiB limit and leaving the phone on direct rendering. The final implementation fixes that gap without reducing resolution or native MSAA quality.

## Final implementation

Static artwork builds into a temporary color/depth render target using the default framebuffer's native MSAA count. A separate fullscreen pass copies the already display-encoded color and resolved depth into a persistent **single-sample** color/depth render target. The temporary MSAA target retires immediately after the copy, including failure paths. Players, ball, moving ground shadows and transparent net grid continue rendering live into the original antialiased default framebuffer. The copy uses public Three.js render targets, textures and a shader; it does not use private framebuffer hooks.

Persistent cache allocation is estimated at **eight bytes per backing pixel** and bounded at **96 MiB**. Build-time peak additional allocation includes both the persistent target and temporary MSAA target, estimated at **48 bytes per pixel** for native 4× MSAA, bounded at **192 MiB**. Both estimates are checked before allocation. These are attachment-size estimates and exclude the unchanged default framebuffer, other scene resources and driver overhead. Oversized surfaces keep direct rendering at full quality; a smaller viewport resumes caching.

At native phone DPR3, persistent cache memory is now **23,699,520 bytes (22.6 MiB)**, an 80% reduction from the previous persistent design. Estimated build-time peak is **142,197,120 bytes (135.6 MiB)**. Default/live and cache-build MSAA both remain **4×**, canvas backing size remains **1170 × 2532**, and the cache is active with zero bypasses or failures.

## Final evidence

- **5/5 cache tests passed** with no skipped or flaky cases: [JSON reporter](verification/cache-memory-final.json), [readable log](verification/cache-memory-final.log). Coverage includes static reuse; camera/light/material/explicit invalidation; resize; exactly-once disposal of initial, resized and temporary targets; oversize peak-budget bypass/recovery; and native-DPR phone quality and memory stability.
- **36 desktop direct/cached pixel cases passed**, with maximum mean RGB channel error **0.0249284 / 255**, maximum pixels differing by more than two levels **0.15744%**, and maximum pixels differing by more than 24 levels **0.010959%**. These maxima match the previous design.
- **36 native phone direct/cached pixel cases passed** across the same four cameras and contact/travel phases. Maximum mean channel error was **0.00806497 / 255**, maximum pixels differing by more than two levels **0.058972%**, and maximum pixels differing by more than 24 levels **0.005638%**. Original thresholds remain 0.6, 1.2%, and 0.2%. Twelve further forced rebuilds retained identical renderer memory counters (40 geometries, eight textures), exactly one resident samples=0 target and zero transient bytes. [Combined desktop/phone pixel, quality and memory evidence](verification/cache-pixel-memory-final.json).
- **30 lifecycle cycles passed**, including one forced context loss at zero-based index 24 while 3D was parked. Re-entry ended with one live canvas, a 1424 × 744 drawing buffer, unchanged renderer memory counters (39 geometries, eight textures), zero browser errors, zero pending animation frames and settled application schedulers. [Lifecycle evidence](verification/lifecycle-memory-final.json).

The checks ran against local preview port 4176 after the runtime fix and before the root-owned restamp/package. The combined pixel and lifecycle evidence identify the implementation by SHA-256; the tested `three-d-playback.js` hash is `a9cdf06ec6147428bc87e4792910023f97b5b81ec96b55c6d0af5328b57512bc`. Previous `version.json` identity refers to the superseded runtime until the final restamp. All owned isolated browsers and contexts closed before the next verification/performance window.

## Acceptance limits and chronology

No meaningful current-scene correctness, resource or visual-quality blocker remains. The existing cache signature and direct-render failure fallback are preserved. Resolved depth can differ from direct multisample output along occlusion edges; these comparisons establish close visual equivalence, not byte-identical output. The results certify the tested Chromium path, not native phone GPU cadence or arbitrary future materials/shaders. Matched performance and final stamped-package verification are separate root-owned checks.

[Earlier four-test acceptance](verification/cache-final-resumed.json), [its pixel evidence](verification/cache-pixel-final-resumed.json), and [its lifecycle run](verification/lifecycle-30-context-loss.json) retain the pre-memory-fix chronology and must not be presented as native-DPR phone acceptance. `verification/cache-checks.log` and `verification/cache-pixel-comparison-initial.json` retain the still earlier failed linear-color experiment as diagnostic history. The final five-test files above supersede those acceptance results.
